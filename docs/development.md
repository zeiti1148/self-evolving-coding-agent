# Git 与开发协作规范

## 1. 分支策略

- `main` 是稳定分支，应始终保持可运行、可评审的状态。
- 每名成员在独立功能分支上开发，不直接在 `main` 上完成日常功能开发。
- 分支名使用简短、可识别的前缀，例如 `feature/agent-loop`、`feature/file-tools`、`feature/experience-store`、`docs/interface-update`。
- 一个分支聚焦一个功能或一组紧密相关的变更，避免混入无关格式化或跨模块修改。

## 2. Pull Request 流程

1. 从最新的 `main` 创建功能分支。
2. 在本人负责的目录中实现并执行相关测试。
3. 推送功能分支并创建 Pull Request。
4. 在 PR 描述中说明变更范围、验证方式、已知限制和是否涉及公共接口。
5. 至少由另一名成员完成审查；问题修正、必要测试通过后再合并。
6. 禁止在未经团队确认的情况下强制推送或改写共享分支历史。

## 3. 模块边界

- 成员一主要维护 `backend/agent/`、`backend/api/` 和整体集成。
- 成员二主要维护 `backend/tools/`。
- 成员三主要维护 `frontend/` 和 `backend/experience/`。
- `backend/shared/` 是三方共同依赖的公共契约目录，由组长协调维护；任何成员修改都必须同步更新 `docs/interfaces.md` 和公共模型测试。
- 不随意修改其他成员负责的模块。确需跨模块修改时，先沟通修改目的、接口影响和合并顺序。
- `docs/interfaces.md` 是公共接口契约。修改函数签名、数据结构、错误码、调用方向或同步/异步约定前，必须由团队确认，并在同一 PR 中更新文档。
- Agent 只能通过 `execute_tool` 使用工具，不直接操作任务业务文件；工作目录生命周期归工具模块负责。

## 4. 提交与审查建议

- 提交信息应说明目的，例如 `feat(tools): add bounded file reader`、`docs: clarify agent result schema`。
- 提交保持可理解，避免将大量不相关变更压在同一个提交中。
- 代码审查重点包括：职责边界、工作目录安全、超时和错误处理、测试证据、敏感信息以及公共接口兼容性。
- 后端公共模型使用 Pydantic v2；新增跨模块数据应优先扩展现有公共模型，避免各模块重复定义同名结构。
- 不把“本地看起来正常”当作测试结果；PR 中只记录实际执行过的命令和结果。

## 5. 禁止提交的内容

- API Key、访问令牌、密码、私钥和真实服务地址中的敏感信息。
- `.env` 等本地配置；仅提交不含秘密的 `.env.example`。
- SQLite 运行文件和本地数据目录，如 `*.db`、`*.sqlite*`、`data/`。
- Python 虚拟环境、缓存、覆盖率输出和构建产物。
- `node_modules/`、前端构建输出和包管理器缓存。
- Maven `target/`、编译生成的 `.class` 文件和测试临时产物。
- Agent 运行时工作目录，包括默认的 `runtime/workspaces/` 和本地配置的其他任务根目录。
- IDE/操作系统生成的个人配置文件。

发现秘密已经进入提交历史时，不应只删除当前文件；应立即通知团队、吊销并更换凭据，再共同决定历史清理方案。

## 6. 合并前检查

- 变更只覆盖本次任务范围，没有误改其他成员模块。
- 文档与实际接口一致。
- 相关自动化测试已实际执行，结果已如实记录。
- `git status` 中没有数据库、密钥、虚拟环境或构建产物。
- 新增配置项已在 `.env.example` 中提供无秘密的示例。
- 没有把 Agent 工作目录及其中的任务代码副本加入暂存区。

第一版任务结束后默认保留工作目录用于检查和调试。确认不再需要后，只能通过经过路径校验的 `cleanup_workspace` 手动清理；不得直接编写宽范围递归删除命令。TTL 自动清理不在第一版范围内。

## 7. 测试目录与执行约定

- `backend/tests/` 放置公共模型以及 Agent、工具、经验、API 的后端单元测试。
- 顶层 `tests/` 放置端到端测试，不用于某个单独模块的私有单元测试。
- 修改 `backend/shared/` 时必须运行公共模型测试，重点检查字段验证、状态一致性和 JSON 往返序列化。
- 缺少 Python、Maven 或其他依赖时应在 PR 中明确记录“未执行”及原因，不能用静态检查代替测试通过结论。
