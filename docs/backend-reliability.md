# 公共模型与任务记录可靠性

本轮在 `experience-v2-integration@721e73a` 基础上，完善公共模型、任务记录和 Agent。
代码提交并上传至 `backend-reliability` 分支，不合并到 main。
Agent 与工具的改动只针对可复现问题。

## 设计与兼容性

1. 适用条件按去掉首尾空白后的精确文本去重，保留大小写、内部空格和原顺序。
   标签继续使用原来的大小写不敏感去重。公共字段、限制、JSON 形状均保持不变。
2. 使用既有 `DATABASE_URL` 对应的 SQLite，在独立的 `api_tasks`、`api_task_steps`
   表保存创建请求、状态、已完成步骤、最终结果和审计。不会重写经验记录。
   相比独立任务数据库，这避免新增环境配置和备份遗漏；相比队列/恢复引擎，
   本次只承担历史记录持久化，不重复执行可能已经修改过代码的任务。
3. API 启动时将遗留的 pending/running 任务原子标记为 stopped，保留已完成步骤，
   提示服务中断、需要重新提交；已结束任务的状态、结果及时间保持不变。
   不宣称恢复运行、撤销代码或自动重试模型请求。仍只支持一个 API 实例和进程。
4. TaskStore 保留无参内存用法；API 显式传入数据库路径。构造不做磁盘 I/O，
   初始化和每次状态变更通过事务完成，线程间通过锁保护访问。文件数据库每次操作
   自动关闭连接；服务关闭先等待后台任务结束，现有实验脚本仍可在关闭后读取审计。
   数据库故障返回安全的 503，不伪装成空历史/404。
5. 已有任务提交、详情和步骤接口保持返回结构不变。新增 GET /api/tasks 提供
   按创建时间及 ID 倒序的历史分页：limit 默认 20、范围 1..100，offset >= 0。
   现有经验页面的“查看来源任务”和任务链接在重启后继续使用。
6. 步骤、计数和状态在同一事务提交；不允许重复步骤、越序步骤、终态改写，
   也不允许最终结果用相同调用 ID 偷换已经记录的参数或工具结果。
   保存最终结果和审计应在同一事务完成；读取均返回独立快照。

## 验收与风险边界

- 公共模型测试覆盖大小写、Unicode、内部空白、精确重复、空条件和 JSON 往返。
- SQLite 测试覆盖关闭/重开、异常中断、线程并发、事务回滚、错误轨迹和损坏数据。
- API 验证提交后重建应用仍可查询详情/步骤，分页、错误状态及经验旧库共存。
- 再运行真实 Maven/pytest 的脚本模型闭环，复验经验来源链接；本轮不调用真实模型。
- 修正 Git 环境相关的测试假设，分别验证仓库内/外临时目录；不改变版本指纹算法。
- 单进程约束保留；之前仅在内存里的任务无法凭空恢复。数据库中的任务描述、
  工具输出及审计属于本地运行数据，与经验一起备份，不提交到 Git。

具体步骤见 [实施计划](superpowers/plans/2026-10-28-backend-reliability.md)。

审查另外发现 Python 的 `True == 1` 会绕过普通对象比较，现按确定顺序的 JSON
内容检查最终轨迹，拒绝把数字改成布尔值，也保留对象字段顺序不影响内容比较的语义。
项目版本断言已同时验证仓库内和仓库外的临时目录，版本指纹算法未改动。

本轮模型是脚本模型，Maven/pytest、HTTP、文件修改和 SQLite 均实际执行。
中断恢复通过预置 pending/running 记录验证，没有声称完成强制杀进程或断电实验。
原始 Java/Python 案例及来源数据库均保持不变。

## 使用与复验

现有启动命令不需要新增配置；沿用根目录 `DATABASE_URL`。不调用真实模型的本机
演示可以使用下面的后端入口，再在第二个终端启动前端：

```powershell
# 仓库根目录；本机这个验收库已包含可查看的任务和经验
.\.venv\Scripts\python.exe frontend/scripts/serve-v2-acceptance.py --data-dir .cache/backend-reliability-20261028/browser

# 第二个终端，从仓库根目录进入前端
cd frontend
npm.cmd run dev -- --port 5173 --strictPort
```

前端的 `.env.local` 使用 `VITE_USE_MOCK=false`、空 `VITE_API_BASE_URL` 和
`API_PROXY_TARGET=http://127.0.0.1:8002`；本机已经配置。
打开 <http://127.0.0.1:5173/>，进入经验记录并点击“查看来源任务”。
也可新提交一个任务，完成后记下 ID，停止并重新启动同一后端，再访问原任务链接。
已完成的步骤、测试结果和经验关联应继续显示。

当前验收任务可直接查看：

- 成功任务：`/#/tasks/740917d4-c9a1-4939-8518-0b74b5cb416f`。
- 模拟中断任务：`/#/tasks/260d9bb3-1e39-49e4-adf4-22ba96000ff5`，应显示任务未完成及保留的 1 条步骤。

历史分页可通过 <http://127.0.0.1:8002/docs> 或 PowerShell 查询：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8002/api/tasks?limit=20&offset=0'
```

跨机器复验无需本机数据库，运行以下已写入工作区的测试与既有脚本即可：

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests/test_task_store.py backend/tests/test_api.py -q
.\.venv\Scripts\python.exe scripts/acceptance_v2.py
```

## 验收证据和保留边界

本机证据位于 `.cache/backend-reliability-20261028/`：
`backend-reviewed.log/xml`、`frontend-final.log`、`build.log`、`contracts.log`、
`repair-final/report.json`、`restart-report.json`、`browser-check.log` 和各阶段失败用例日志。
截图位于 `frontend/output/playwright/backend-reliability-20261028/`。
这些数据库、截图和运行报告被 Git 忽略；代码、测试和本说明可随功能分支交付。

审查边界：全量回归和实际工具由主执行者复验；已有 V2 行为仅做回归，不重新评审其
全部实现。单实例限制保留，尚未验证断电、强制终止和永久卡住的连接关闭；当前优雅
关闭会等待后台任务完成。结果/审计落库失败时先尝试记录安全的失败终态，连失败状态
也无法保存时才对该任务和历史列表返回 503，避免把未记录的任务当作成功。

仍未实现自动续跑、取消、独立任务历史页面、Diff 接口及多 worker 调度。旧内存任务
和以前已经被条件去重丢弃的文本无法补回。交付目标为 `backend-reliability`，
保持 `main` 和 `experience-v2-integration` 分支不变。
