# V3 对照实验与经验检索

用户已授权直接实施：先补齐 V3 对照实验，再优化经验检索。目标是提供可复现的修复效果比较，而不是预先声称效果提升。

## 范围与选择

- 保留旧 `scripts/experiment.py` 和历史报告；新增 V3 入口，避免改变旧实验含义。
- 采用已有 Java/Maven、Python/pytest、SQLite、FastAPI 和模型客户端，不新增依赖或更换模型服务。
- 使用独立训练、人工审阅发布后的经验库只读快照。评估保存到独立数据库，禁止反馈到本轮参考库。运行前检查来源与目标仓库隔离。
- 经验条件为 `none/full/compact`；完整与精简使用相同检索策略和候选，精简保留规则、适用条件和能力要求，仅删除辅助元数据。
- 检索策略为 `baseline/contextual`；baseline 重现空查询旧排序，contextual 使用任务和失败测试上下文、标识符与中文词片段匹配及保守去重。语言、仓库、发布状态、能力与异常类型约束仍为硬过滤。
- 可分别运行 single/multi；相同配置固定模型、步数和时限，条件轮换排序，每项任务多次独立运行。
- 提供六个目标案例（每种语言三个），来源训练与目标评估分离；原始源码和测试不被实验改写。
- 报告记录全部失败、实际请求中的引用 ID/哈希、模型及用量、验证测试、源码版本、冻结库哈希、每组汇总和配对差值。缺失用量不按零成本解释。
- 默认只打印计划，不读取密钥、不发请求、不建立运行目录；真实运行显式 `--live`。复用项目现有配置，缺失配置明确 `not_run`。

## 不同方案

直接扩展旧脚本会混淆历史实验的固定 Java 两组合同；完全重写执行引擎会重复受控工具与最终验证逻辑。选择独立 V3 调度器，复用生产 Agent/API 和只读冻结库基础设施。

## 验收

单元测试覆盖条件轮换、快照隔离、来源泄漏、格式精简、中文/标识符相关性和硬过滤；真实工具配合确定性模型验证两种模式的接线。全量后端测试和现有前端契约检查验证兼容。真实模型试验单列结果，不能把确定性模型结果解释为能力提升。
