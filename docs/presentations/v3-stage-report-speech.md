# 第三阶段汇报简短演讲稿

对应 9 页 PPT，建议用时约 5–6 分钟。每页同样的讲稿已写入 PPT 备注，可直接使用演讲者视图。

口径：2026-11-01 重跑回归；V3 完整脚本验收采用 2026-10-31 记录。真实模型结果与脚本模型结果分开说明。

## 第 1 页：具备自演化能力的 Coding Agent 系统设计与实现

大家好，这次汇报的是第三阶段，时间是十月二十六日到十一月一日。我们在已有自动修复流程上，重点完成复杂任务、多条经验、仓库隔离、通用发布和多 Agent 协作。目标是让每条经验都有来源和测试依据，让后续任务可以在明确条件下复用。接下来会分别介绍功能、实际验证和下一阶段计划。

## 第 2 页：01 本阶段开发范围

本轮按 M0 到 M6 推进，技术栈保持不变。先保留可靠性优化和基线，再完成多经验保存、隔离合并和通用发布，随后接入运行时角色协作，最后完成页面联调与异常验收。这里的完成指代码和工程流程验收。V3 的真实模型验证还没有完成，需要在后面的计划里单独补齐。

## 第 3 页：02 一次成功修复，直接生成多条经验

以前一次修复主要保存一条记录，现在一次提取可以直接产生多条独立经验。复杂样例分别形成文本输入、整数输入和集合选择三组知识，适用条件各不相同。程序把这些记录绑定到真实最终测试，再一次性保存。我们实际让第二条保存失败，确认整批回滚。这里三条经验共享一次十八项测试的证据，不能把测试数量重复累计。

## 第 4 页：03 仓库隔离、合并与通用发布

仓库隔离是这次的重点。所有角色只能使用当前仓库的专属经验，或者已经发布并满足条件的通用经验。项目经验不能直接变成通用记录，需要先预览、编辑，再明确发布。合并时检查规则和条件是否冲突，重复操作不会产生重复记录，来源也不会被删除。发布后的模型内容不携带原仓库路径等私有信息。

## 第 5 页：04 跨仓库复用按目标业务验证

跨仓库复用不能简单照搬来源代码。比如来源项目把空姓名设为 guest，目标要求 visitor；来源数量越界时回退，目标要求抛异常。验收中，发布前目标没有收到来源专属经验，发布后实际模型请求包含通用经验。Java 和 Python 的目标都通过各自十二项测试。这个结果证明当前流程按目标规则完成验证，但还不是效率提升的证据。

## 第 6 页：05 多 Agent 协作与程序协调

多 Agent 不是把同一对话重复调用几次。诊断、修复和复核都有独立上下文，并共享任务的步数和时间。修复角色只提交提案，程序先核对文件哈希和版本，复核通过后统一应用。最后再由程序独立执行测试。即使模型说修好了，只要测试没过就不能算成功。预算耗尽会停止，重启也不会自动重放修改。

## 第 7 页：06 页面联调与持久化展示

前端沿用原来的深浅色风格，增加执行模式、角色过程、多条经验链接和仓库筛选。这张图来自实际页面，展示已发布通用经验及其适用条件。我们在浏览器完成来源修复、合并发布、目标复用和单模式任务，并在 API 重启后重新查询，确认任务、经验和来源关系仍然存在。这里使用真实后端，模型响应采用脚本替身。

## 第 8 页：07 实际验证结果与当前限制

提交前重新运行后端四百九十八项测试、前端八十七项测试，构建和接口联调都通过。此前 V3 的十三个脚本任务覆盖了成功流程，也包含预算耗尽、角色异常和保存失败等预期负例。需要说明，早期 V2 有真实模型记录，但 V3 缺少完整配置，目前真实调用为零。三组对照也还没做完，所以我们不宣称更快或更省 token。

## 第 9 页：08 下一阶段计划与建议分工

下一阶段首先配置真实模型，检查多条经验是否具有独立用途，以及角色协作和跨仓库复用是否可靠。然后完成无经验、完整经验和精简经验三组对照，统一任务和预算，统计成功率、调用次数、token 和耗时。建议三人分别负责 Agent、样例实验、经验与展示，最后交叉复现并评审代码，形成可复现的答辩版本。我的汇报结束，谢谢大家。

## 可能被问到的问题

**为什么脚本模型通过，还要验证真实模型？**

脚本模型用于控制响应，证明程序能够正确调用工具、隔离经验、处理失败并保存数据。真实模型能否独立定位复杂问题、生成有价值的多条经验，需要单独验证。

**多 Agent 是否已经提升效率？**

还不能这样说。当前证明了角色独立调用、受控交接和独立测试的流程。三组对照未完成，可能增加调用和 token，也可能改善复杂任务表现，需要用统一实验比较。

**跨仓库经验会不会影响目标项目原来的规则？**

通用经验需要人工编辑和显式发布，检索还会按语言与能力过滤。目标始终使用自身固定测试；默认值、范围和异常策略不同的样例已纳入脚本验收，但这不能保证任意新业务都正确。

**为什么运行库没有备份文件？**

准备阶段配置的运行数据库不存在，所以没有创建空库充当备份。项目交付了使用 SQLite backup API 的备份脚本，并通过真实 SQLite 和 WAL 测试。
