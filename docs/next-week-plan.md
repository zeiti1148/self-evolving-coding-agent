# 第三阶段计划：复杂经验与多语言仓库修复

周期：2026.10.26—2026.11.01。开发基线：main@6527421。开发分支：feat/experience-evolution-v2。

## 本周目标

把当前单异常 Java 修复闭环扩展为能够处理多异常、复用组合经验，并支持 Java / Python 项目仓库的原型。五项能力必须接入 Agent、API 和 Vue 工作台，提供实际执行记录。

| 工作项 | 具体实现 | 建议负责人 | 验收条件 |
| --- | --- | --- | --- |
| 复杂经验 | 保留原摘要、根因、方案；增加语言、仓库、适用条件、多问题明细、修复顺序、结构化测试证据 | 成员一与成员三 | 一个成功任务保存至少两个问题；能在页面查看每个问题对应的根因、措施和文件；旧 SQLite 数据可读 |
| 经验合并 | 先预览兼容性与冲突，再生成新的合并经验；保留原始记录、来源 ID 和验证证据 | 成员三 | 重复合并幂等；不同语言、仓库或冲突方案不会被静默混合；检索优先使用合并后的有效记录 |
| 一个样例多个异常 | 增加组合缺陷样例；测试失败反馈后继续修复；最终所有验收测试通过才保存成功经验 | 成员一与成员二 | Java 和 Python 各有组合缺陷案例；保留初始失败、部分修复仍失败、最终通过的执行轨迹 |
| Java 之外的语言 | 首先支持 Python / pytest，按登记项目选择测试执行器；保留 Java / Maven | 成员二 | 两种语言都能读写工作副本、执行真实测试；测试和构建配置受保护；零测试、跳过和超时不视为成功 |
| 项目仓库经验 | 登记可信本地仓库，绑定稳定仓库 ID、语言和来源版本；同仓库经验优先，通用经验单独标识 | 成员一与成员三 | 页面可选择登记项目；仓库 A 的专属经验不进入仓库 B；任务和经验能追溯来源仓库及版本 |
