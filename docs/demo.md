# 答辩演示操作说明

下方保留历史 single 演示；当前 V3 使用本节的新流程。先按 README 准备 JDK、Maven、Python 和前端依赖，并在本地 `.env` 配置模型。密钥不出现在截图、PPT、演示录像或 Git 中。


## V3 页面演示（先脚本模型，再真实模型）

脚本模型演示有实际 API、SQLite 和 Maven/pytest；浏览器 mock 只展示合成数据，不作为验收。

根目录启动脚本模型服务，所有产物落到独立 `.cache` 目录：

```powershell
.\.venv\Scripts\python.exe frontend/scripts/serve-v3-acceptance.py --port 8003 --data-dir .cache/v3-demo
```

另一终端启动 Vue（保留已有 `.env.local`，使用本进程环境覆盖）：

```powershell
$env:VITE_USE_MOCK = 'false'
$env:API_PROXY_TARGET = 'http://127.0.0.1:8003'
npm.cmd --prefix frontend run dev
```

打开前端终端输出的页面地址（通常是 `http://127.0.0.1:5173`）；`8003` 是后端接口端口，直接访问其根路径会显示 404。

内置样例、角色过程、演示经验、合并与发布说明均使用中文。更新代码后，先停止并用原命令、**相同的 `--data-dir`** 重启演示后端，再刷新前端并点击“填入修复示例”。新任务使用中文说明，已有任务和经验保留原始记录；代码中的默认值、路径、异常名和原始测试输出不作翻译。

1. 选择 **Python 结算项目：六处缺陷修复**，选 **多 Agent 协作**，填入示例并提交。也可选择单 Agent 模式演示。
2. 展示两次独立诊断、修复提案、独立复核、程序应用与最终验证。角色意见不是成功依据；展开最终 pytest，确认 18 测试、零失败/错误/跳过。
3. 结果区点击每条经验链接，核对文本/整数/集合三组独立用途，各两个相关问题，共享同一次真实最终测试证据。展示来源任务和批次。
4. 经验页筛选 Python、仓库 `v3-python-checkout`，选择其中两条，预览并确认合并。查看来源图，原记录仍存在。对已被其他合并占用的来源再次组合应显示冲突，不覆盖。
5. 从合并记录进入通用化预览，编辑规则和适用条件，例如“边界检查顺序可参考；默认值、整数范围和拒绝策略必须以目标测试为准”。填写真实所需能力 `integer-input, indexed-selection`，检查最终注入内容，显式发布。
6. 切到 **Python 预约项目：跨仓库经验复用**，多 Agent 提交原始任务。它要求 visitor、非法数字回退 1、数字越界抛错、无效索引 unassigned，不能照搬结算项目的 guest/0/none。确认目标全部 12 测试通过。
7. 单独运行 `scripts/acceptance_v3.py` 查看逐角色 `actual_injections` 与 ID/哈希；页面结果只能证明测试，不能仅据经验列表宣称模型收到它。报告包含发布前零注入和发布后已发布 ID 注入。
8. 刷新任务及经验详情；停止演示 API 后用**相同 data-dir** 重启，原任务、角色事件、经验和来源链接仍可读取。中途断开的任务标记 stopped，不自动续跑。
9. 切换深浅主题，复查发布编辑器、角色时间线和来源图。用单 Agent 模式跑一个结算样例，确认多个经验链接和旧单 ID 兼容。

## 通过链接查看测试源码

1. 打开一个已有任务，在“最终结果”或展开的测试步骤中点击 **查看测试源码**。
2. 源码页显示该任务工作副本中的测试文件，可切换文件、按行阅读。长代码可在代码区域横向滚动，代码按原文显示。
3. 点击 **复制源码链接**。粘贴到新标签页后直接回到同一任务、同一文件；也可手动复制页面中的“直接访问链接”。
4. 刷新后文件选择仍保留。点击 **返回任务** 查看真正的测试输出和最终结果；打开源码不会重新执行测试。

## 通过链接查看修复前后代码

1. 在任务“最终结果”中点击 **查看修复前后对比**；也可直接点击“修改的文件”中的文件名。
2. 左侧切换文件，右侧红色 `−` 为删除、绿色 `+` 为新增，同时显示原行号和新行号。长行默认自动折行，可取消勾选恢复横向滚动。
3. 点击 **修复前原文** 或 **修复后原文** 查看完整文件。空文件和不存在的文件会分别标明。
4. 点击 **复制对比链接**，新标签页或刷新后仍打开同一任务、同一文件、同一查看方式。可从对比页进入测试源码或返回最终结果。

## 历史 single 成功流程

1. 根目录运行 `.venv/Scripts/python.exe -m uvicorn backend.api.main:app --host 127.0.0.1 --port 8000 --workers 1`。
2. 前端设置 `VITE_USE_MOCK=false`，运行 `npm run dev`，打开输出地址。
3. 在新建任务页点击“填入修复示例”，保留 20 轮预算并提交。任务使用原始 GreetingService 的独立工作副本。
4. 观察运行中已完成的工具步骤。展开源文件读取、写入和 Maven 测试步骤；模型的一次工具失败不等于任务最终失败。
5. 任务结束后分别核对“代码修复”“最终测试”“经验记录”。只有独立最终测试通过才能显示成功；确认修改文件是应用源文件。
6. 打开经验记录，展示根因、修复方法、验证调用 ID 及来源任务。当前任务、角色事件、测试步骤及经验均持久化；重启后可继续查询已完成记录。
7. 使用 `scripts/acceptance.py --live` 展示第二个 Profile 样例的复用证据。该脚本使用另一份独立数据库，不能把其经验误当作页面默认数据库中的记录。

2026-10-25 的页面验收任务为 `02745b70-fa65-4df8-9e49-fcf2b1c7655e`：真实模型 deepseek-flash，6 个工具步骤，最终 2 项测试通过，保存经验 `9b4ac439-156f-45ff-9646-98e0e2dc7108`。本地证据为 `.cache/ui-live-report.json` 与 `ui-live-*.png`；页面截图也放在仓库同级阶段文档目录的“演示素材”。重启后该任务 ID 仅用于证据对应，不保证可再查询。

## 异常说明与演练

- 断开后端后刷新经验列表，页面应显示“服务暂时不可用，请稍后重试”，而不是切换为模拟数据。已实测该场景。
- 预算耗尽：用 1 轮预算提交原始样例。真实模型的工具选择不确定；系统的确定性预算行为由 `backend/tests/test_agent.py` 中对应测试证明，状态应保持 stopped，不能仅因某次测试通过就宣称完成。
- 最终测试失败：源代码仍有缺陷时，最终 Maven `TEST_FAILED` 对应 `tests_passed=false`；构建、环境或超时故障对应 `null`，避免把未完成验证写成断言失败。
- 经验保存失败：单测覆盖提取 JSON 无效和存储异常。它们保留已完成的修复成功，另显示经验保存失败。不要为了演示破坏真实数据库；需要可重复展示时使用前端现有模拟场景，并在演示中注明。

## 讲解边界

“自演化”在当前版本指成功经验的积累、检索和注入，不是修改模型权重。是否有用要看固定样本上的有无经验对照，不能由一次复用成功推断普遍提升。此原型用于本机可信项目，任务状态持久化但不自动续跑，工作副本默认保留；路径保护和命令白名单不是操作系统沙箱。
