## 结果解读

1. **本案例存在成功率上限。** 无经验已能成功修复，所有条件均为 1/1；本轮无法区分哪种方法更容易修复困难问题。这是同一案例的六次运行，并非六个独立案例。
2. **新检索尚未表现出明确优势。** 对应完整经验组的 token 比旧检索少 1.48%，耗时多 32.53%；对应精简组的 token 少 0.44%，耗时多 3.74%。这些是单次观测差异，不能当作稳定增益或退化。
3. **精简表示没有降低本轮总 token。** 旧检索下 compact 比 full 多 2.28%，新检索下多 3.35%。四个经验组的用量也都高于各自的无经验组。参考 JSON 从 5717 字节降至 5308 字节，不代表整条修复过程必然节省用量。
4. **仍需更多独立样本与重复次数。** 两个 none 条件均关闭检索，实际处理方式相同，用量仍分别为 30,307 与 27,850，显示运行波动。当前候选仅 3 条，小于 Top-5 容量，两种检索保留同一组经验，主要区别是排序，尚未检验大量候选下的筛选效果。本轮每条件仅一次且按计划顺序执行，无法排除运行顺序影响。
