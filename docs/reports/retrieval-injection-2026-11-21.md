# 经验注入：失败不撤出与预算参数化（2026-11-21）

对应阶段五设计第三节。本轮只做两件事：修正"检索暂时失败会清空已注入经验"的缺陷，并把注入预算显式化、写入审计。没有做引用追踪与真实对照，见文末。

## 起点核查（与原计划不同）

原计划写的是"跨轮次按 rule_id 去重、只追加新规则"。核对代码后不成立：

- `backend/agent/core.py` 在**每个决策轮开头**重新检索并整包替换参考经验，注释写明原因是"并发合并/发布可以在任务中途使参考失效"。如果改成累积，已经失效的规则会被继续注入，破坏这条安全不变量。
- 同一文件里 `update_references()` 对 payload 的写入会被下一轮替换覆盖，属于无效写入。
- 多 Agent 的 `run_role()` 也是"每个角色重新检索后替换"，但它先由 `capture()` 检索一次、再由 `run_role()` 检索一次，两次之间失败会把已取到的参考清空。

因此本轮改为：**失败不撤出、成功才替换**，并把成本治理交给预算参数化，而不是累积。

## 改动

1. 单 Agent（`backend/agent/core.py`）
   - `retrieval_error` 改为"只描述最近一次检索"：成功时清空，失败时置位。
   - 决策边界处：只有"检索成功"才替换参考经验；检索失败时保留模型已经看过的内容。
   - `update_references()` 不再写 payload（写入必被覆盖），只刷新审计事件。
2. 多 Agent（`backend/agent/orchestrator.py`）
   - 同样的"最近一次失败"标志；`run_role()` 在检索失败且结果为空时保留角色已有的参考经验。
3. 预算参数化（`backend/experience/policy.py`）
   - 新增 `RETRIEVAL_BUDGETS` 与 `retrieval_budget()`：baseline/contextual 为 5 条 / 16000 字符，adaptive 为 3 条 / 8000 字符；未知策略回退到 contextual。
   - 单 Agent 按策略把 `limit` 和 `character_budget` 传给检索。
4. 审计
   - 每次注入记录 `reference_limit`、`character_budget`、`injected_characters`；任务审计顶层也记录当次预算。

## 实测（本机，2026-11-21）

| 测试集 | 结果 |
| --- | --- |
| 新增 `test_retrieval_withdrawal.py` | 3 项通过 |
| 新增 `test_retrieval_budget.py` | 4 项通过 |
| Agent / 多 Agent / 经验策略 / 检索配置相关 8 个文件 | 86 项通过 |

行为验证：

- 首次检索成功、之后每次抛错的夹具：第一次和最后一次请求里都仍带着该规则（失败不撤出）。
- 首次成功、之后成功但无匹配规则：第一次请求带规则，最后一次为空（成功即撤出）。
- 先失败两次、第三次成功且无匹配：仍在恢复后的那一轮撤出（错误标志不会被旧失败一直占用）。
- adaptive 策略下检索收到 `limit=3, character_budget=8000`，contextual 收到 `5 / 16000`，审计字段与之一致。

## 限制与未做

- 多 Agent 的"失败保留"路径只有间接覆盖（既有 `test_adaptive_retrieval.py` 的多角色用例），没有新增专门的失败夹具；这条不变量目前属于实现说明，不是独立回归。
- 预算取值（adaptive 3 条 / 8000 字符）是初始设定，尚未用真实任务验证是否合适；需要阶段三 3.4 的 6 对 × 2 策略对照才能判断。
- 引用追踪（3.3：模型是否真的用了注入规则）没有做。现有的 `injection_events` 只记录"注入了什么"，不记录"是否被引用"。
- 本轮没有真实模型调用，没有新增付费请求。

## 后续
