## 五项能力的实现

| 工作项 | 本轮结果 | 验收依据 |
| --- | --- | --- |
| 复杂经验 | 保存语言、仓库、适用条件、有顺序的问题数组、对应文件与最终测试证据；旧 SQLite 数据可继续读取 | 两种语言各保存一条包含 3 个问题的成功经验，详情页面展示根因和修复措施 |
| 经验合并 | 提供预览与确认，检查冲突、保留来源与证据，相同来源重复合并返回同一记录 | API 与页面操作通过；合并记录再次进入真实模型上下文 |
| 多异常处理 | 首个问题修好后若仍有失败，反馈具体异常并继续决策，最终独立测试通过后保存经验 | 脚本模型驱动真实工具，保留初始失败、部分修复仍失败、全部通过的轨迹 |
| 多语言 | Java 使用 Maven，Python 使用隔离解释器运行 pytest；执行器由登记项目决定 | 两种语言各 12 项真实测试全部通过；原有 Java 样例回归通过 |
| 项目仓库经验 | 本地项目登记、稳定仓库 ID、Git 版本与工作副本内容哈希；同仓库优先检索 | 跨仓库专属经验隔离、项目选择及来源版本记录均通过 |

经验处理流程：**任务所属仓库与语言 → 检索适用经验 → 注入模型上下文 → 多问题修复与测试 → 保存结构化经验 → 预览合并 → 后续任务检索合并结果**。

## 运行与团队接手

1. 按 README 安装后端、前端依赖和 Maven，配置本地 `.env`、JDK 路径；密钥不提交到仓库。
2. 启动 FastAPI 与 Vite，在任务页选择 Java 或 Python 的组合异常样例。
3. 提交任务，观察三个模块的修复；成功后进入经验详情查看结构化记录。
4. 使用 `python scripts/register_project.py --help` 查看本地仓库登记方式；设置 `PROJECT_REGISTRY` 后重启服务。
5. 团队评审本分支，扩充真实项目、补充合并冲突案例，再进行独立的经验复用对照评估。
