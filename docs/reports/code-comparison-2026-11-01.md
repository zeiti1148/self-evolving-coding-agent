# 修复前后代码对比与整体检查（2026-11-01—11-02）

## 功能与处理方式

任务结果增加“查看修复前后对比”，修改文件名可直接进入对应文件。页面显示红色删除行、绿色新增行、前后行号及三行上下文；支持修复前/后完整原文、长行折行、文件切换、复制直达链接和刷新恢复。保留深浅色主题与手机布局。

现有工作副本原先只有创建时哈希，不能把当前项目文件直接当作旧版本。因此分两种情况：

- 新任务：创建时保留限量原文，任务结束时以临时文件加原子替换保存一次快照；之后项目与工作副本的变化不会改写历史对比。快照位于工具可写目录之外。
- 旧任务：原文必须匹配创建时哈希；新版本必须来自成功写入记录，并匹配保留的工作副本。页面明确标明这种来源。不能核对时拒绝显示，不补造前后内容。

保存快照失败不会覆盖修复状态、最终测试或经验保存结果；缺少结束快照的新任务不回退到当前代码。新增、删除和空文件分别表示，单纯换行变化会单独提示。当前支持 Java/Python 业务代码，限制单文件 200000 字节、每侧快照总原文 2000000 字节、100 个修改文件、单版本 4000 行在线差异；超限会提示。

## 整体检查与优化

- 测试源码和代码对比共用任务与工作副本归属校验，继续拦截越界、链接、测试/配置及凭据路径。
- 修正测试源码页切换文件时重复读取目录的问题：两次文件查看的目录请求从 2 次变成 1 次，正文仍重新读取。切换任务会清空缓存、取消旧请求，迟到响应不会覆盖新任务内容。
- 快照采集达到总量限制后跳过额外正文读取，避免继续读取无法保存的内容。
- Java 示例常把整个方法写在一行，增加默认折行显示，让改动条件在手机和桌面都可读。
- 最后边界检查修正了空文件新增/删除被误判为“仅换行变化”的情况，补上两种断言并重跑全部 20 项代码对比测试。
- 新的只读验收脚本会核对每个版本的 SHA-256、增删计数和任务记录不变，不重新修复项目。
