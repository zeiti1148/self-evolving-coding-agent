# 真实案例：label(None) 判空经验的自动归并

本次在三个独立工作副本中重放此前模型生成的真实修复，实际运行 pytest，并调用生产 `ExperienceStore.save_experiences` 与 `MaintenanceWorker`。没有调用手动合并接口，也没有新的模型 API 请求。

经验输入固定复用此前真实提炼结果中的一条判空规则，以单独验证重复学习后的自动归并。这不是三次新的模型推理，也不是不同措辞的语义合并准确率实验。

## 具体错误与经验

原始代码 `label(value)` 直接返回 `value.strip()`，所以 `label(None)` 触发 `AttributeError`。采用此前真实修复里的 None 判断和空白归一化后，三个独立副本分别从原始 11 项测试中 8 项失败，恢复到 11 项全部通过。

本次保存的规则原文是：

> 在调用 strip 前增加 None 判断：if value is None: return 'guest'；再对非 None 文本执行去除首尾空白。

语言、仓库、文件/符号、兼容版本、适用条件、完整约束和该条规则正文保持一致。每次来源任务、保存时间和测试调用编号不同。每次证据来自该次实际执行，没有把旧的测试结果复制成三份新证据。

## 实际数据库变化

| 实际步骤 | 原始经验 | 规范规则 | 独立测试证据 | 模型引用 |
|---|---:|---:|---:|---:|
| 第 1 次保存，后台检查前 | 1 | 1 | 1 | 0 |
| 第 1 次后台检查完成 | 1 | 1 | 1 | 1 |
| 第 2 次保存后 | 2 | 1 | 2 | 1 |
| 第 3 次保存后 | 3 | 1 | 3 | 1 |
| 重试第 3 次的相同保存请求 | 3 | 1 | 3 | 1 |

规范规则 ID 始终为 `3b61101c-3aaa-58b7-963d-513e1f77faa5`。后续相同规则在保存事务中命中同一指纹，只增加来源关联和唯一测试证据；首次规则经后台检查后才能引用。三条原始经历和对应来源都保留，最终只向模型提供一条规则，`verified_runs=3`、`minimum_tests=11`。

这不是将三条原始记录物理删除后拼出一条新正文，而是保留原始资料，将重复知识归到同一条规范规则。复现脚本直接断言原始项目未变、原始经历未改、引用来源包含全部三条、相同保存重试不增加条目。
