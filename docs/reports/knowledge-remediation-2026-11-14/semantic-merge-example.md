# 不同任务原文的自动语义合并实录

日期：2026-11-14。复现入口：`scripts/demo_semantic_experience_merge.py`。完整机器记录：[semantic-merge-example.json](semantic-merge-example.json)。

## 本次实际展示了什么

从既有真实修复实验中读取两次任务各自提炼的完整经验，保留原始 ID、文字、约束、依赖、时间和测试证据，将它们导入新建的隔离数据库，再运行生产环境使用的维护作业及本地语义模型。

本例来自项目的小型修复基准：两次任务共享 `quantity` 的初始缺陷与业务契约，各自执行修复并产生不同的补丁和经验原文。第二次属于原实验的旧策略评估组。它证明了不同任务产物的语义归并流程；样本规模不足以代表复杂业务仓库的准确率。

本轮没有新增模型 API 请求，没有改写经验、降低 0.95 门槛、手动插入等价关系或人工确认合并。来源数据库及模型校准文件的 SHA-256 在运行前后相同。

## 两条原文

| | 任务 A | 任务 B |
|---|---|---|
| 运行 | `training-python-independent` | `evaluation-python-independent-old-r2` |
| 任务 ID | `66d5330d-c8be-4a42-90e6-65fc3e5fd6ce` | `7be175c8-3ef2-441d-8dd7-10f0b9419e74` |
| 经验 ID | `a4861a4b-c256-4007-a48b-d1dcf134ab84` | `7733be83-1564-4be4-8339-e81d6717d341` |
| 根因原文 | quantity 直接调用 int(value)，未先判断 None；当输入为 None 时，int(None) 抛出 TypeError。 | None 输入未判空，直接调用 int(value) 会触发 TypeError。 |
| 方案原文 | 在解析前增加 None 判断：if value is None: return 0。 | 在解析前先判断 value is None，若为 None 立即返回 0。 |
| 原任务验证 | 11 项通过 | 11 项通过 |

两条规则的指纹不同：`41043c6f-b32a-5ea2-abf4-a5151aa4fe1f` 与 `5fb98be2-adc8-5806-ab6d-52578dce978f`。完整约束和根因也不同，精确指纹去重不能把它们变成同一条记录。

本轮另外建立两个独立工作目录，重跑各自的原始测试与已保存的真实补丁。两组均从 **11 项中 8 项失败** 变为 **11 项全部通过**。这属于旧补丁的独立复验；没有冒充新模型修复。另实际执行 `None`、空串、空白、非法文本、负数和合法整数等七种输入，输出保存在 JSON 中。

## 自动判断和实际输出

使用固定版本的 [mDeBERTa NLI 模型](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-mnli-xnli) 分别做两个方向的自然语言推断，每项取两个方向中较低的蕴含分数。额外检查错误类型、代码目标、版本、前置依赖及受保护事实。

| 检查 | 实测分数 | 门槛 |
|---|---:|---:|
| 适用条件 | 0.993819 | 0.95 |
| 完整规则 | 0.985079 | 0.95 |
| 单独修复动作 | 0.994469 | 0.95 |

这些是模型评分，不是“合并正确率”。作业自动写入 `equivalent` 关系，人工决定表有 **0** 条记录。

检索 `TypeError` 时实际返回 **1 份引用**，方案采用任务 B 的原句：

> 在解析前先判断 value is None，若为 None 立即返回 0。

这份引用的 `source_ids` 包含 A、B 两个原始经验 ID；`evidence_summary.verified_runs = 2`，`minimum_tests = 11`；来源分页也能查询到两份经验。两条原始经验及其共 6 条子规则仍完整保存，仅选中的判空知识归为一份引用。其余子规则没有被宣称自动合并。

## 演示中发现并修复的不足

1. **共同条件抬高整段评分。** 真实 `read + None → guest` 与 `write + None → ValueError` 曾被旧整段检查判为等价，分数为 0.995525。本次增加修复动作独立双向推断后，动作分数只有 0.150622，结果为 `unknown`，不合并。另一个 None 处理与空白处理的跨错误类型误合并也被拦截。门槛维持 0.95；未删除旧失败记录。
2. **语义归并后来源没有汇总。** 以前引用只带代表规则自身的来源，遗漏同义规则的独立证据。现在对完整等价组汇总来源，以任务与工具调用标识去重验证证据；暂停或失效成员不参与活动引用。使用 [SQLite DISTINCT](https://www.sqlite.org/lang_select.html#distinct) 实现集合去重，而非累加证据链接数。
3. **无关错误的未知关系阻塞查询。** 现在先选当前错误类型及其完整前置依赖，再检查它们能否共同引用。真实冲突与全局暂停仍先行生效；前置依赖的未知关系仍会阻塞。两个来源前置依赖不同的候选不折叠，避免遗漏修复步骤。

## 验证及限制

- 新增 9 项回归，涵盖共同上下文误导、动作常量、跨错误类型、来源汇总、证据去重、前置依赖和暂停成员。全量后端 **637 通过、1 跳过**。
- 用冻结校准重新运行 600 对受控规则：0 误合并，17 对同义规则转为 unknown；保留集 294 对在该受控数据上全部符合标签。未重新调参。
- 16 对补充反例：0 误合并，仍漏识别 4 对真实冲突；仅 2/4 同义对自动判定。详见 [新增动作检查验证](semantic-action-guard-validation.json)。
- 两个真实反例也从旧 `equivalent` 转为 `unknown`。unknown 表示自动判定不足，不能当作已经证明矛盾。
- 另一个来自 read-only 与 read/write 任务的候选虽通过语义评分，但前置依赖不同，仍保留独立规则。没有为演示删除依赖。
- 这是一例从真实产物中选出的成功演示，不用于估计总体语义合并率。初步筛查的 240 对候选及失败结果保存在 `.cache/knowledge-semantic-real-audit`；16 对挑战与跨任务真实反例说明一般 NLI 尚不能保证代码语义正确。
- 原 108 次任务的报告保留原样，本次改动后的重放与新增验证单独归档。

## 复现

在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/demo_semantic_experience_merge.py
```

冻结校准的 600 对规则和 16 对补充反例验证可用 `scripts/knowledge_action_guard_validation.py` 单独重跑。

需要既有 `.cache/knowledge-live-experiment` 原始实验材料、`.cache/knowledge-semantic-real-audit` 筛查记录以及本地固定模型。脚本缺少原始资料时会失败，不会自动创建伪造经验，也不会联网请求模型。每次创建独立目录并校验全部断言；最新成功结果输出至本报告同目录的 JSON。
