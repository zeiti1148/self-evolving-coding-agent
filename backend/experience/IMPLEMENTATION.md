# SQLite experience module implementation plan

> Execution: superpowers:executing-plans, using test-driven-development.

Goal: implement the three synchronous experience functions in docs/interfaces.md
without changing shared models, Agent, tools, API, frontend, or dependencies.

Architecture: sqlite3 storage with per-operation connections; existing Pydantic
models at the boundary; an injectable ExperienceStore and module-level facade.
The facade reads DATABASE_URL when called, not during import. Relative database
paths resolve against the repository root. Explicit store paths support tests.

Spec: docs/interfaces.md sections 3.3 and 5, backend/shared/models.py, and the
user-approved M0–M2 workflow in this chat.

## Constraints and decisions

- Python 3.11+, sqlite3 standard library, existing Pydantic v2; no new packages.
- Only backend/experience and backend/tests/test_experience*.py are changed.
- Public save/search/list signatures remain unchanged and synchronous.
- UUIDs and aware UTC timestamps are generated by storage; tags use JSON.
- Blank tags are rejected, matching the current shared model (the prose about
  dropping blanks is inconsistent and has been reported).
- Keywords are whitespace-separated literal substrings, all must match at least
  one searchable text field. Unicode casefold is used for matching.
- Tags match whole values, case-insensitively, with AND semantics. Error type
  matches a whole value case-insensitively. All filter categories combine by AND.
- Empty query means no keyword restriction. Empty tags mean no tag restriction.
- Order by created_at DESC, id DESC; all filtering precedes LIMIT.
- limit must be a positive integer, offset a nonnegative integer; bool rejected.
- No implicit dotenv loading; the API/bootstrap supplies environment variables.
- Invalid arguments use EXPERIENCE_VALIDATION_ERROR; storage/configuration or
  corrupt-row failures use EXPERIENCE_STORAGE_ERROR with safe messages.
- Each operation owns and closes its connection. Imports never create a database.
- Existing DATABASE_URL=sqlite:///./data/app.db is supported; :memory: is rejected
  because per-operation connections would silently lose its contents.
- source_task_id is provenance, not a foreign key to an absent task table.
- Work in the approved current checkout on codex/experience-store; no additional
  worktree or cross-module housekeeping changes. Leave changes for user review.

## Review focus

1. Unicode and SQL wildcard characters match literally, never alter SQL.
2. Invalid or corrupted data never becomes fake success or an empty result.
3. Background-thread writes work without sharing SQLite connection objects.
4. Calling from another working directory uses the same configured database.
5. Transactions close/roll back; repeated initialization preserves prior data.
