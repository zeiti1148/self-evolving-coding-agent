# 复杂经验、仓库检索与合并

经验 V2 保留原来的摘要、异常、根因、方案、验证、标签及来源字段，增加下列内容：

| 字段 | 用途 |
| --- | --- |
| `schema_version` | 旧数据库记录读取为 1，新记录默认 2 |
| `language` | `java` 或 `python` |
| `scope` / `repository_id` | 通用经验，或只适用于某个仓库的经验 |
| `source_revision` | 产生记录时的源码版本 |
| `applicability` | 适用条件 |
| `issues` | 按修复顺序保存每个异常的根因、措施和相关文件 |
| `evidence` | 独立最终测试的任务 ID、工具调用 ID、执行器和测试计数 |
| `merged_from` | 合并的直接来源经验 ID，可继续追溯原记录 |

`RepairIssue` 包含 `error_type`、`root_cause`、`solution`、`files`。`VerificationEvidence` 只接受正测试数、零失败、零错误和零跳过；Java 对应 Maven，Python 对应 pytest。Agent 从真实工具结果构造证据。旧记录没有结构化计数时保留原验证文本，通过来源 ID 查询原始任务。

问题文件统一为相对 POSIX 路径，`./src/a.py` 和 `src//a.py` 会归一为 `src/a.py`，同一路径只保留一次。目录穿越、设备名和不可移植的路径组件被拒绝；合并比较再次使用规范路径，兼容已有数据库中路径的不同写法。

## 兼容迁移

连接数据库时在事务中检查原 `experiences` 表，添加 `details` JSON 列。旧九列的内容、ID、时间和排序都保留。新增记录的扩展字段存入 `details`，读取时经过同一 Pydantic 契约校验。

新增 `experience_merges` 保存来源集合对应的合并结果，`experience_merge_sources` 保存每条被合并记录的替代记录。原始经验不删除。迁移使用写锁串行检查，避免多工作线程同时首次访问发生竞态。

## 检索

`retrieve_experiences(query='', *, language, repository_id, error_types, limit=5)` 排除被替代的记录，筛选同语言及同仓库/通用经验。存在异常类型时要求与主异常或问题明细至少匹配一种。排序依次为同仓库优先、异常覆盖数、关键词匹配数、创建时间与 ID。

检索按游标逐条评分，用有界候选堆保留最多 `limit` 条完整记录，不在内存中累积整库经验对象。

旧 `search_experiences` 的参数和组合匹配语义保持一致，也排除已被合并取代的记录。`list_experiences` 默认保留全部历史，可选 `language`、`repository_id`、`scope`、`active_only`，筛选发生在分页之前。`get_experience` 根据 UUID 查询，包括历史来源，缺失返回 `None`。

## 合并

1. `preview_merge` 接受 2—10 个不同来源 ID，返回 `can_merge`、`conflicts`、`source_ids` 和 `preview`。
2. 只有语言、作用域、仓库及适用条件一致的记录可以合并。同异常且文件范围重叠时，根因/方案不一致会产生冲突。
3. 合并按原记录顺序保留问题规则，并同时满足各源记录的修复顺序。顺序冲突形成循环时拒绝合并。
4. 验证证据按任务 ID 和工具调用 ID 去重；相同调用的证据不一致时拒绝合并。组合内容超过字段容量时要求减少来源，不截断知识。
5. `merge_experiences` 在一个写事务中重新检查来源、保存新记录和建立全部关系。相同来源集合重复或并发合并返回同一结果。已用于其他合并的源记录应改用当前合并结果继续合并。
6. 普通 `save_experience` 不接受手填 `merged_from`，防止绕过来源检查。事务失败会回滚新记录及合并关系。
